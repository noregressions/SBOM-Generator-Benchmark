# GitHub Dependency Graph SBOM export

**What it is.** GitHub computes a dependency graph for every repository from its manifests and exposes it as an SPDX 2.3
document through the REST API (`GET /repos/{owner}/{repo}/dependency-graph/sbom`) and the "Export SBOM" button on the
Insights tab. Free for public repos; included with GitHub Advanced Security / Dependabot for private ones.

**Install.** `brew install gh && gh auth login` · [docs](https://docs.github.com/en/rest/dependency-graph/sboms)

## What `run.sh` demonstrates

| Step | Capability shown |
|---|---|
| 1 | Export the SPDX SBOM for a public repo (default `CycloneDX/cyclonedx-maven-plugin`; pass `owner/repo` to change) |
| 2 | Summarise detected ecosystems from the purls (Maven, GitHub Actions, GitHub repos) |
| 3 | Explains the **Dependency Submission API**: push a build-resolved graph (Maven/Gradle/any SPDX) so the export and Dependabot
    cover transitives that cannot be inferred from a pom. `.github/workflows/sbom.yml` in this repo does this with Syft and the Maven action |

## What we saw

- 116 packages for the Maven plugin repo, generated by GitHub with protobom; GitHub Actions used in workflows appear as
  `pkg:githubactions/...` components, which no local tool reports.
- The export is only as good as the graph: for Maven and Gradle it is manifest-inferred unless a submission action runs.

## Strengths / limits

- Strengths: zero setup, always available, includes Actions dependencies, feeds Dependabot.
- Limits: SPDX only, no hashes, no file-level data, needs network and auth; accuracy depends on submission for JVM builds.
