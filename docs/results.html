What the columns mean

Under each test case is the number of shipped components the tool named at the exact version, out of all that ship in that test case. The denominator is the same at every stage. A dash means the tool was not run there.

Total found
Shipped components named at the exact version, summed over the test cases this tool ran on at this stage. The second number is how many ship in those test cases, so it differs between tools that ran on different cases.
Cases
How many of the test cases that have this stage the tool ran on. A tool is not run where it does not support the ecosystem or the kind of input.
Wrong purl
Components named with the right name and version but under the wrong group or namespace, so no vulnerability database will match them. Lower is better.
Leaked
Things that do not ship (test, dev and build tooling, provided-scope and BOM imports) listed as if they did, with nothing a consumer could filter on. Lower is better.
Labelled
Things that do not ship, listed with a scope or property that marks them as such. This is the correct way to include them, so a high number is not a fault.
NTIA 2021
Score out of 10 against the NTIA minimum elements for an SBOM (2021): supplier, name, version, identifiers, dependencies, author, timestamp.
NTIA/CISA 2026
Score out of 10 against the 2026 NTIA/CISA revision of the minimum elements, which adds hashes, licences and more.
BSI v2.1
Score out of 10 against the German BSI technical guideline TR-03183-2 version 2.1, which asks for more per component than the NTIA lists do.

Wrong purl, Leaked and Labelled are counts of components, summed over the tool's documents at that stage. They are not percentages. The three baseline columns are averages of the tool's documents at that stage, each scored out of 10 by sbomqs.

Hidden dependencies: who names them, and where

The components each test case was built around. They reach the artefact, or shape it, without appearing in an ordinary dependency list.

One square per stage the test case has, in the order source, artefact, image: Y named at the right version, v wrong version, p wrong purl, n not named, · tool not run at that stage. A Y means the purl matched; it does not say why (a shaded jar can be "found" from a leftover metadata file).
