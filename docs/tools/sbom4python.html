  • In scope: package components whose purl type is one of the test case's ecosystems (OS packages in images are ignored).
  • Shipped found: recall against what is really in the artefact, at the exact version.
  • Wrong ver: named, but at a version that does not ship. Wrong purl: right name and version under the wrong group, so no advisory database will match it.
  • Leaked: things that do not ship (test, dev, build tooling, provided, BOM imports) listed with nothing a consumer could filter on.
  • Labelled: the same things listed with a scope or property that marks them, which is correct. +N counts further labelled components outside the known list.
  • Hashes ok: hashes that match the real digest of the jar inside the built artefact, over hashes the tool emitted for those jars.
  • NTIA 2021, NTIA/CISA 2026, BSI v2.1: sbomqs compliance totals out of 10. They measure whether the fields are present, not whether the inventory is right.

Hidden dependencies

One square per stage the test case has, in the order source, artefact, image: Y named at the right version, v wrong version, p wrong purl, n not named, · tool not run at that stage. A Y means the purl matched; it does not say why (a shaded jar can be "found" from a leftover metadata file).
