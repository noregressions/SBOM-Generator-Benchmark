The application and how it is built

A Python application whose requirements.txt names one package, reportkit. reportkit's metadata requires tracehook-demo, which is available only as a source distribution. When pip installs it, pip runs the build backend the package nominates, tracehook_backend, and that backend generates the module that gets installed.

What gets hidden, and how

Installing a source distribution means running code the dependency supplies. The installed files are the output of that code, and the transitive dependency is not written anywhere in the application's own files.

Reading the result

From requirements.txt alone a tool cannot name tracehook-demo, because it is not written there and has to be resolved. A tool that reads the installed environment can. None can say that the module's contents were generated at install time. pip is also in the environment, as tooling, and a tool that lists it without a mark counts as a leak here.

This is our interpretation. The counts above are what the run recorded; why a tool found or missed something is inferred from how the tool works, not established by the data. Limits of the benchmark.
