The application and how it is built

A Node application with one dependency, trace-route-package. The package's entry point is dist/index.js, but dist/ is not in the package's source. A prepack lifecycle script, scripts/generate-dist.js, writes it when the package is packed, and the script itself is left out of the tarball that gets installed.

What gets hidden, and how

npm runs a package's lifecycle scripts while the distributable is being made. What is installed can therefore differ from what is in the package's repository, and the code that made the difference never ships.

Reading the result

A tool that reads the lockfile can name the package. None can tell that its contents were generated, because an SBOM identifies a package by name and version and says nothing about how its files came to be. Scanned on its own as an installed directory, the package has no lockfile beside it, which leaves a scanner little to go on.

This is our interpretation. The counts above are what the run recorded; why a tool found or missed something is inferred from how the tool works, not established by the data. Limits of the benchmark.
