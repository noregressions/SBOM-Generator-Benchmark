How it is measured

The advisories Grype returns for exactly the components that ship, taken from the ground truth, are the reference: what a true SBOM would raise. Every component each tool's SBOM names is then looked up in the same database, by package URL, and each advisory that comes back is put in one group.

Advisories found
Advisories that apply to what ships and that this SBOM would raise, out of all that apply. Higher is better.
Missed
Advisories that apply to what ships and that this SBOM would not raise, because it leaves the component out or names it wrongly. Lower is better.
False alarms
Advisories raised against components known not to ship, which the SBOM lists with nothing to mark them. Lower is better.
Filterable
Advisories raised against components the SBOM lists and marks as not shipping (test, dev, build tooling). A consumer can filter these out.
Wrong version
Advisories raised against a shipped component at a version that does not ship.
Other
Advisories raised against a component in neither list. At the image stage these are mostly the server's own libraries.

What this is not. It is a lookup, not a security assessment. An advisory against a component does not mean the vulnerable code is reachable. The counts are advisories, not components, so one badly out-of-date library can account for many. They will change as the database does. Several test cases use old versions on purpose, so that there is something to find.
