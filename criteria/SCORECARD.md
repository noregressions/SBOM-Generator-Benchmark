# SBOM Generator Index scorecard: content accuracy vs baseline conformance

Generated by `criteria/score.py` from `criteria/output/`. Test cases are in `testcases/`; ground truth is in `testcases/<name>/expected.json`. Every target is scanned at up to three stages: **source** (the checkout, minus build outputs and caches), **artefact** (the built jar/war/tarball/venv) and **image** (the container).

Column meanings: *in scope* = package components whose purl type is one of the target's ecosystems (OS packages in images are ignored). *Shipped found* = recall against the list of what is really in the artefact, version-exact. *Wrong ver* = named, but at a version that does not ship. *Wrong purl* = right artifact and version under the wrong group/namespace, so no advisory database will match it. *Leaked* = things that do not ship (test, dev, build tooling, provided, BOM imports) listed with no scope/property a consumer could filter on. *Labelled* = the same things listed **with** such a label, which is correct (a `+N` is further labelled components outside the known list, typically the rest of the build tooling). *Unexpected* = in-scope components in neither list (at image stage these are mostly the server's own libraries). *Hashes ok* = tool hashes that match the real digest of the jar inside the built artefact, over hashes the tool emitted for those jars; checked at every stage, since the shipped jar is the reference whichever stage the document came from.
